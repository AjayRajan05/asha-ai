# Support policy

ASHA **v0.4.2** is a developer preview. Support for the open-source project is **best-effort**; there is no paid SLA.

## Channels

| Need | Where |
|------|--------|
| Questions / design talk | [GitHub Discussions](https://github.com/AjayRajan05/ASHA/discussions) |
| Bugs / features | [GitHub Issues](https://github.com/AjayRajan05/ASHA/issues) |
| Chat (optional) | [ASHA Slack](https://join.slack.com/t/asha-community/shared_invite/zt-45h11ellh-yY~YG4BL8W~TvxsMXSgPzw) |
| Security | Email per [SECURITY.md](https://github.com/AjayRajan05/ASHA/blob/main/SECURITY.md) (never public issues) |
| Contributing | [contributing.md](contributing.md) |

Canonical short policy: [SUPPORT.md](https://github.com/AjayRajan05/ASHA/blob/main/SUPPORT.md) in the repo root. Docs site: [ajayrajan05.github.io/ASHA](https://ajayrajan05.github.io/ASHA/).

## Expectations

- Maintainers respond when available; response times are **not guaranteed**.
- Pin `asha==0.4.2` for pilots so upgrades are intentional.
- Prefer a minimal repro over large private code dumps.
- Hardened models and ANCHOR framework extras are optional (see [status.md](status.md)).

## Before opening an issue

1. Check [troubleshooting.md](troubleshooting.md) and [faq.md](faq.md).
2. Confirm your extras and env vars (`ASHA_DISABLE_ML`, `ASHA_MODELS_DIR`, …).
3. Use an issue template when available.
